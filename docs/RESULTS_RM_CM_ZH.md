# RM / CM 小规模真实训练：第一轮结果

## 结论

**已训练并保存两个自行训练的 LLaVA-1.5-7B 评分模型，完成真实前向、反向、更新以及保存后重新加载。RM 出现明显的帮助性偏好学习信号；CM 在内部验证上没有达到可用的安全成本区分水平，当前不应直接接入 RL。**

这是一轮小数据、LoRA 训练验证，不是作者原始 checkpoint，也不是论文的全参数训练复现。两个模型的训练跑通，不能等同于最终策略已接近论文效果。

## 实验范围

- 128 条训练、32 条内部验证，均来自固定版本 BeaverTails-V 的 **train split**。
- 覆盖五类：动物虐待、危险行为、虚假信息、金融与学术欺诈、隐私侵犯与监视。
- 两个模型均从 LLaVA-1.5-7B 基座独立初始化，训练 2 个 epoch。
- 训练语言部分 LoRA、图像投影层和评分头，冻结视觉编码器。
- 所选训练/验证图像互不重复，并排除与已用 590 条 evaluation 图像的精确重复。这里只检查解码后图像一致，不保证不存在近似图像或语义重复。
- 没有修改标签，没有新增 judge，没有运行 RL。

## 结果

这里的“排序准确率”是 **RM/CM 对数据已有两个回答的标量评分排序是否符合人工标签**：RM 更高分应对应更有帮助的回答，CM 更高成本应对应另一条较不安全的回答。相同分数记为不正确，与训练实现一致；它与之前的策略平均 token 概率一致率不是同一个指标。

| 指标 | 训练前 | 训练后 |
| --- | ---: | ---: |
| RM 内部验证排序准确率（32 对） | 31.25% | **84.38%（27/32）** |
| CM 内部验证排序准确率（32 对） | 50.00% | **46.88%（15/32）** |
| CM 内部验证安全标签准确率（64 个回答，阈值 0） | 56.25% | **54.69%（35/64）** |
| CM 内部验证平衡安全标签准确率 | 43.90% | **43.64%** |
| RM 训练集排序准确率（128 对） | — | 78.13% |
| CM 训练集排序准确率（128 对） | — | 64.06% |

### 如何理解

- **RM 有正面信号，但证据很小。** 验证仅有 32 对回答、单随机种子、五类数据；每一对会改变约 3.13 个百分点。不能因 84.38% 看起来较高就宣称复现了论文效果。
- **CM 的 loss 下降不代表安全能力达标。** 验证 loss 从 2.288 降至 2.017，但排序准确率没有提高。把所有验证回答都判为多数类“安全”，准确率可达 64.06%，高于本轮 CM 的 54.69%。
- CM 对验证中的有害回答平均成本略高于安全回答，但两组均为负值、间隔很小，说明不能仅凭均值方向正确就认为成本模型可靠。
- 保存后重新加载的抽查评分与保存前一致，确认产物可重载；**尚未验证 RL 加载、优化器断点续训或多卡训练**。

## 资源实测

本轮两个模型各使用一张 H20，并行训练，不需要占满八张卡。

| 项目 | RM | CM |
| --- | ---: | ---: |
| GPU 数 | 1 | 1 |
| PyTorch 峰值 allocated 显存 | 15.36 GiB | 15.36 GiB |
| PyTorch 峰值 reserved 显存 | 16.68 GiB | 16.68 GiB |
| 纯训练累计用时 | 231 秒 | 230 秒 |
| 单模型任务总用时（加载、训练、验证、保存及重载） | 360 秒 | 358 秒 |
| 保存的 adapter 目录 | 约 97 MiB | 约 97 MiB |

实际 `nvidia-smi` 占用略高于 PyTorch allocated；上述资源仅适用于本轮的 LoRA、每步 1 对回答和最长 2,048 token 配置，**不能用于估计全参数训练显存**。产物必须搭配固定版本基座和本项目评分模型实现加载，不是独立完整权重。

## 距离论文效果还有什么

论文 §5.3 / Table 4 给出的参考结果为：

| 训练偏好对数量 | RM 排序准确率 | CM 排序准确率 | CM 安全/有害符号准确率 |
| --- | ---: | ---: | ---: |
| 5K | 82.2% | 54.5% | 66.1% |
| 15K | 84.5% | 79.3% | 87.8% |
| 30K | 86.3% | 80.4% | 89.7% |

**当前 128 条训练 / 32 条内部验证不与这张表构成可比实验。** 模型更新方式、数据规模、验证样本与评测口径尚未对齐，也未取得作者实际训练配置与原始评分模型。因此不能计算可信的“距离论文还差几个百分点”。论文结果也提示 CM 对数据规模更敏感，但不能据此认定本轮 CM 失败只由数据不足造成。

## 下一阶段

1. **已准备并启动第二轮**：20 类、1,024 条训练＋256 条内部验证，保留现有训练配置，不用已评的 590 条 evaluation 调参；同时排除第一轮所用图像，作为新的规模诊断。当前进行第 2 个 epoch，尚未完成最终评估与保存重载。第 1 个 epoch 的内部验证排序准确率暂为 RM **79.30%（203/256）**、CM **77.34%（198/256）**；CM 零阈值安全标签准确率 **78.71%**，高于该验证集 **59.38%** 的多数类基线。只是中间检查，不作为最终结果或论文对照；新旧验证集不同，也不能把两轮差值解释成严格的数据规模消融。
2. 核对论文与公开配置、准备完整训练环境，推进**冻结视觉编码器、训练语言模型＋投影层＋评分头**的全参数路线。独立环境已完成原始 RM/CM trainer 导入与 CUDA 优化器扩展编译，但尚未运行真实全参数训练；明确记录公开默认值与作者实际配置未知的部分。
3. 先做小规模全参数真实训练与保存恢复验证，再向论文 5K/15K 数据规模靠近；CM 的排序、符号区分与各类别结果必须一起检查，不能只看 loss。
4. 评分质量与加载稳定性通过后再短程 RL，最后验证最终策略。未达标的 CM 不用于宣称安全改进。

作者原始 RM/CM 仍未取得；本地 judge 继续暂停。论文最终策略的成对胜率评测仍未复现。
