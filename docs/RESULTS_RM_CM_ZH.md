# RM / CM 真实训练：LoRA 结果与全参数试训

## 当前结论

**第二轮 20 类 LoRA 训练已完成：RM 与 CM 都出现了明确的内部验证学习信号，CM 不再停留在第一轮的失败状态。值得继续做更接近公开配置的训练。**

- RM 排序准确率：**47.27% → 78.52%（201/256）**。
- CM 排序准确率：**46.88% → 80.08%（205/256）**。
- CM 零阈值安全标签准确率：**56.25% → 80.47%（412/512）**，高于本验证集 **59.38%** 多数类基线；平衡准确率 **79.91%**，AUC **0.883**。
- 两个 adapter 已保存并从新加载的基座重载，抽查分数差异均为 **0**。

可以说 **LoRA 复现了有希望的评分学习趋势**，不能说已经复现论文最终策略效果。评分模型对已有回答排序，不等于 RL 后模型生成回答的帮助性或安全性胜率。

## 第二轮范围与结果

1,024 条训练＋256 条内部验证，覆盖全部 20 类；从固定 LLaVA-1.5-7B 基座分别重新训练 RM、CM，2 epochs、单种子。

- 所有样本来自固定版本 BeaverTails-V **train split**，验证不是论文测试集。
- 语言 q/v LoRA、完整图像投影层和评分头，冻结视觉；每步 1 对回答、梯度累积 4。
- 新样本排除第一轮已用图像及已用 590 条 evaluation 的精确图像重复，内部 train/validation 图像不相交。未完成语义或近重复去重。
- 固定完成 2 epochs，不因第 1 epoch 的 RM 准确率略高而选取它；没有在 evaluation 上调参。

| 内部验证指标 | 训练前 | 训练后 |
| --- | ---: | ---: |
| RM 排序准确率（256 对） | 47.27% | **78.52%（201/256）** |
| CM 排序准确率（256 对） | 46.88% | **80.08%（205/256）** |
| CM 安全标签准确率（512 回答，阈值 0） | 56.25% | **80.47%（412/512）** |
| CM 平衡安全标签准确率 | 49.27% | **79.91%** |
| CM response-level AUC | 0.483 | **0.883** |

排序准确率检查 RM 更高分是否对应更有帮助的回答、CM 更高成本是否对应较不安全的回答；tie 判错。安全标签指标检查 `cost > 0` 是否对应有害回答；AUC 的 tie 权重为 0.5。这些不是之前的策略 token 概率一致率，也不是独立生成安全准确率。

最终训练集排序准确率为 RM **84.67%**、CM **74.32%**。验证集更小且构成不同，不能从训练/验证数值差异单独判断泄漏或可靠性；本轮只证实精确图像排重和内部学习信号。还需要更大样本、类别诊断与独立冻结评测。

## LoRA 资源实测

RM/CM 各单张 H20 并行，不占满八卡。

| 项目 | RM | CM |
| --- | ---: | ---: |
| PyTorch 峰值 allocated 显存 | 15.47 GiB | 15.47 GiB |
| PyTorch 峰值 reserved 显存 | 16.68 GiB | 16.68 GiB |
| 纯训练累计用时 | 31.05 分钟 | 30.91 分钟 |
| 加载、训练、评估、保存与重载总用时 | 41.72 分钟 | 41.60 分钟 |
| 优化器更新 | 512 步 | 512 步 |
| 保存 adapter | 约 97 MiB | 约 97 MiB |

上述时间为本次实测，不是全参数训练预测；显存不含其他进程，`nvidia-smi` 通常略高于 allocated。Adapter 必须配固定基座，不是独立完整权重；尚未验证这些 LoRA 产物的 RL 加载和优化器续训。

## 第一轮作为历史对照

首轮只用五类、128 条训练＋32 条内部验证：RM 31.25% → **84.38%（27/32）**，CM 50% → **46.88%（15/32）**；CM 安全标签准确率 **54.69%** 低于 **64.06%** 多数类基线。这轮 CM 不可用。每模型训练约 230 秒、总体约 6 分钟，峰值 allocated/reserved 为 15.36/16.68 GiB。

第二轮与第一轮数据规模、类别和验证集均不同，结果说明扩展后的方案有正面信号，但不是严格的单因素数据规模消融，不能断言第一轮失败只由数据少造成。

## 小规模全参数试训：v1 记录与修正轮

已执行独立新样本的 **20 类、256 条训练＋64 条内部验证、3 epochs**，4 卡 ZeRO-2，RM/CM 串行，不启动 RL 或 judge。训练完整语言骨干、投影层和评分头，冻结视觉及未连接标量损失的词表头。全局 batch 16、lr 3e-5、betas 0.9/0.95、weight decay 0、warmup 3%、regularization 0.001；RM constant_with_warmup、CM cosine。

### v1：有学习信号，但加载认证存在缺口

训练源版本 `08d3537aa488be6959898695fb2b7dbd1288fdbc`，两模型各完成 48 次优化更新：

| 内部验证结果 | RM | CM |
| --- | ---: | ---: |
| 最终排序准确率 | 82.81%（53/64） | 65.63%（42/64） |
| 最终训练集排序准确率 | 99.22%（254/256） | 未生成最终 summary |
| CM 零阈值安全标签准确率 | — | 78.91%（101/128） |
| CM response-level AUC（训练执行路径） | — | 0.860 |
| 原 runner 完成标记 | DONE（只抽查一对重载分数） | 无 DONE；独立模型重载检查失败 |

**这些不是已认证的部署产物。** RM 虽通过原来的单对抽查，但排查 CM 时发现两者共享的执行差异：DeepSpeed 的 BF16 转换还舍入了一个不随权重保存的位置编码 buffer；独立 HF 加载时该 buffer 为 FP32。一对抽查不足以认证完整重载协议。v1 模型与失败产物保留，不放宽容差，不冒充完整成功。

诊断确认保存的 HF/DeepSpeed **所有权重键及 tensor 均完全一致**。CM 第一对分数差 0.0078125；只对齐该 buffer 后完全一致。64 对诊断中，两种执行路径最大分数差 0.017578125，虽本轮排序计数和零阈值计数恰好不变，仍不能据此绕过加载合同。工程细节见 [开发记录](development/RM_CM_TRAINING_ZH.md)。

### 修正轮 v2：工程验收通过，CM 质量未达标

训练源 `ded1afc618e8ea1aa934294d5fff569e52bd460b`，同一 256/64 数据、预定 3 epochs/48 updates，从固定基座重训。新 run 保留 v1、不放宽容差；RoPE 为原生 FP32，重载检查覆盖全部 64 对及相同分布式 batch 组成。两模型 checkpoint 恢复、fresh 重载的最大分数差都为 **0**，完整验证排序一致，CM 零阈值判定一致；optimizer moments 恢复与真实恢复后更新也通过。

| 内部验证指标 | RM | CM |
| --- | ---: | ---: |
| 训练前排序准确率 | 45.31%（29/64） | 60.94%（39/64） |
| 最终排序准确率 | **85.94%（55/64）** | **56.25%（36/64）** |
| 最终训练集排序准确率 | 99.22%（254/256） | 50.78%（130/256） |
| CM 零阈值安全标签准确率 | — | 51.56%（66/128），等于多数类基线 |
| CM 平衡安全标签准确率 | — | **50.00%** |
| CM response-level AUC | — | 0.621 |

**RM 有学习信号，但训练拟合很强；CM 质量不合格，不能接 RL。** CM 最终把所有 128 个验证回答都判为安全，其中 62 个有害回答全部漏检；其训练集同样全部判安全。权重保存和可重载不等于模型可用。按预定最后 epoch 报告，不挑中间 epoch；不把 v1 更高的 CM 指标当成选择旧执行精度的理由，也不凭单轮断言精度修正是全部质量变化的原因。

每模型训练约 4.8 分钟，全流程 RM **9.16 分钟**、CM **9.26 分钟**；各 rank 最高 allocated/reserved 为 **61.77/64.51 GiB**，包含扩展的 fresh 验证。v1 的 57.91 GiB allocated 不能代替 v2 峰值。最终权重及优化器体积量级仍约 101 GiB/模型，HF 只存完整推理权重及 metadata。

下一步按用户顺序适度扩大训练（约 1K 量级）与冻结内部验证，重点排查 CM 绝对项、梯度/分数趋势及校准，不直接跳论文规模、不启动 RL。作者最终 RM/CM 尚未取得，不能直接做作者评分 checkpoint 对比；以后训练出策略才比较作者公开最终策略与我们的策略，同样本、同生成设置，评分诊断不能替代论文策略胜率。本地 judge 继续暂停，不调用付费 API。

### 下一轮：1,024/256 全参数扩展

用户允许适度增加规模；准备新的20类 **1,024条训练＋256条内部验证**，排除两轮LoRA、前轮256/64及已用evaluation的精确图像重复，最长2,048 tokens、不截断。新验证集固定后不用于选择中间epoch；与前轮验证集不同，不能把准确率差直接当成规模消融。

保持全参数ZeRO-2、4卡、每卡4对、全局16对、3epochs，RM/CM串行；每模型192updates，warmup `int(192*0.03)=5`，其余优化配置不变。从固定基座重新训练，不续接小模型断点。新增逐步损失分项及**标量score空间**梯度诊断，不改变原loss或模型梯度；它们不是参数梯度，更不是RL指标。

启动前重新检查GPU，继续只选择四张明确空闲卡，不把空闲快照当预留。根据上一轮预估每模型纯训练约20分钟、完整流程25–40分钟，显存按约60–75GiB/卡预留；这些是预算，待本轮实测替换。每模型含optimizer约100GiB量级，训练样本增四倍不会把checkpoint增四倍。数据准备和工程预检不代表已完成1K训练，后续以DONE/summary及完整验证重载为准。
