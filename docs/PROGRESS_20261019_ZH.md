目标是在相同策略起点、训练量、有效反馈预算及共同配方下，验证 Joint-Gradient 相对 Uniform-CV 和 Marginal-Gradient 的安全性—帮助性表现。

### 固定比较规模

- 固定执行顺序：**Uniform-CV → Marginal-Gradient → Joint-Gradient**。
- 每个方法 **16 个池，每池 32 条 fresh on-policy 回答，查询 4 条反馈**，共 64 条训练反馈。
- 三方法训练反馈共 **192 条**；共同 base 及三个方法终点各评估 64 条，共 **256 条评估反馈**；合计 **448 个逻辑反馈 slots**。
- 各方法从同一策略起点、同一 **192 观测** ONS 初态开始；base 和终点评估标签不更新 ONS。
- 三方法使用同一组 **512 条新 PTX 行**，各自独立记录消费；方法内不重放，也不复用历史已消费的 32 条 PTX。
- 一般八状态、全部 **6,759,919,616 个可训练 actor 坐标**、先合并优势再 PPO clip、同 actor 点累加 PPO+PTX 后一次 step、按实际反馈揭示顺序更新等要求保持不变。没有改用仿射、sketch 或参数子采样。

这是持续委托下的开发比较规模，不是逐项 UI 选定的正式验收规模。评估题已使用，不是独立盲测、未见任务泛化验证或正式留置 B。

## 3. 真实 7B 一致性问题：保留失败，再做实际验证

### 首次完整池预检确实失败

第一次无更新预检已生成 32 条回答，但在全坐标 Gram 计算中遇到**相同参数块间实际 G 梯度平方范数重复不一致**，退出码为 1，没有完整几何成功证据。

检查发现该预检入口遗漏了训练入口已有的严格确定性设置。这起初只是候选原因，不能仅靠源码检查就宣布修复。原失败、原源码绑定和原输出均保留，没有通过放宽容差、删除重复检查或减少坐标覆盖绕过问题。

### 默认/严格模式重复梯度诊断

随后对两个预先指定的真实样本/状态点进行诊断，包含穿插其他梯度计算后的重复控制，共 **12 次实际反传**：

| 检查 | 未开启确定性算法 | 开启严格确定性算法 |
| --- | --- | --- |
| 两个测试点的全坐标重复梯度 | 两组均不完全一致 | **两组均逐字节一致** |
| 重复间变化坐标数 | 两组均大于 0 | **两组均为 0** |
| 最大绝对差、平方 L2 差 | 非零 | **全部为 0** |

覆盖每次全部 **6,759,919,616 个 FP32 可训练坐标**。actor 状态未变，没有 optimizer step、新回答、反馈请求、PTX、ONS 或正式 B 消耗。

结果支持“预检遗漏严格确定性设置”这一解释，但两个测试点本身不能替代完整八状态几何复核，也不证明所有未来更新点都已验证。

## 5. 反馈与监督链：已测试的范围与新增恢复授权

已有独立全池 packet 核验、反馈桥、receipt/ACK 分离、终点评估核验、actor-only 安全保存及单 SSH 监督器等离线实现。共同运行链的一轮离线集成为 **64 tests / 44.544 秒 / OK**；这是该轮源码版本的工程证据，不是实际 7B 训练结果。

用户随后明确授权：已归档为 FAILED 的发送，可以由监督器**有日志地启动新的单次 sender 进程**恢复同一条回答。该权限单独追加冻结，不将原零重试授权静默改写为隐藏重试。

- **每个 sender 进程最多一次 network send，首次失败即退出**；后续进程使用新物理 ID，保留原问题、图片、回答、候选、池、查询和上下文。
- 全部成功和失败累计受 2,048 次总上限约束，并受现有等待时限约束；不另增有效标签预算。
- **RESERVED 不确定请求阻断补发**；已有 durable SUCCESS 但子进程丢失返回时，读取同一 receipt，零第二次发送，父状态 ONS 只提交一次。
- **ACK write/flush 不确定即终止**，不重放 ACK，不重连 SSH，不自动重启远端 policy。

后续恢复专项测试为 **20 tests / 44.774 秒 / OK**，包含真实本地独立子进程、合成 transport、SQLite durable receipt、失败后新进程、RESERVED 阻断、成功丢返回零重发、总上限最后一次成功的零发送读回及 ACK 边界。

两轮测试不同，**不拼接成单次完整集成通过**。本地 subprocess/fixture 测试不是 live SSH 或真实外部反馈训练验证；最新完整 runtime/source/per-arm launch 绑定和端到端接线仍待完成。
