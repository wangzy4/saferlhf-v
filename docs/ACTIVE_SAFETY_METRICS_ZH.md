# RM/CM 的 sigmoid 指标是什么意思？

## 简短回答

这两项是**固定自训评分模型对回答的平均自动评分**，不是 PK 胜率，也不是人工测得的帮助性/不安全率。

- **RM（Reward Model）**：帮助性奖励模型，原始分数越大表示模型越偏好该回答。
- **CM（Cost Model）**：安全成本模型，原始分数越大表示模型认为回答越不安全；因此这个 cost 指标通常越低越好。
- `sigmoid` 只是把无界分数压到0–1。**数值落在0–1不自动等于校准概率。**

## 具体怎么计算

对第 i 个图文问答，固定评分器产生一个回答末端标量 `z_RM,i` 或 `z_CM,i`，分别变换：

\[
\sigma(z)=\frac{1}{1+e^{-z}}.
\]

例如，原始分数−1、0、1分别映射为约0.269、0.5、0.731。sigmoid单调递增，不改变单个评分器的回答排序。

报告的64题指标是**先对每条回答做sigmoid，再取均值**：

\[
\overline r=\frac1{64}\sum_{i=1}^{64}\sigma(z_{\mathrm{RM},i}),\qquad
\overline f=\frac1{64}\sum_{i=1}^{64}\sigma(z_{\mathrm{CM},i}).
\]

这不等于对64条原始分数的均值做sigmoid。后者一般会得到不同结果。

## 为什么新算法用了这个变换？

v2.1理论接口要求已知reward和自动成本proxy处于[0,1]，所以本次采用固定的sigmoid映射：

- `r = sigmoid(raw_RM)` 作为自动reward；
- `f = sigmoid(raw_CM)` 作为自动成本proxy。

这是统一尺度的工程选择，不是已经完成概率校准的声明，也不是根据此次64题结果拟合的变换。

特别是RM主要从**两份回答的相对偏好**学习。成对排名loss通常依赖分数差，给所有分数加相同常数不改变这种排名loss，却会改变每条分数的sigmoid值。因此不能把单条sigmoid(RM)解释为“这条回答有多少概率是有帮助的”。CM虽也有安全标签训练和零阈值验证，但本次没有完成独立人类风险概率校准。

## 本次64题结果应怎样读？

同一冻结题集、匹配的greedy解码，固定同一套自训RM/CM：

|指标|base-before|active-after|后−前|
|---|---:|---:|---:|
|平均sigmoid(RM)|0.487916|0.499581|+0.011665|
|平均sigmoid(CM)|0.549254|0.554148|+0.004894|

合理解释：

- 同一RM给新回答的平均有界自动reward略高。
- 同一CM给新回答的平均有界自动cost也略高，**不是自动安全成本改善信号**。
- 未做统计显著性检验；RM/CM本身也用于训练，因此不是独立真人判官。

**不合理的解释：**

- “帮助性准确率从48.79%提高到49.96%。”
- “训练后55.41%的回答不安全。”
- “奖励上升，所以算法已证明整体改善。”

不同RM/CM权重、分数尺度、题集、模板或分词方式之间也不能直接把这个均值当作统一质量量表比较。本次是将保存的decoded回答加空白分隔的assistant prefix和EOS重新分词，before/after按同一流程评分；不是对原生成token tensors的直接评分。

## 与其他数字的区别

|数字|实际含义|
|---|---|
|Luna PK胜率|Luna在成对回答中强制选谁更好，分母为格式有效对战；不是RM/CM sigmoid|
|RM/CM验证排序准确率|评分器在带偏好标签的回答对上排序是否正确；不是生成策略胜率|
|CM零阈值安全标签准确率|raw CM以0分界的分类表现；不是上述平均sigmoid|
|训练代理池成本估计|结合AI-proxy标签、主动采样概率和LURE/control-variate校正的估计；不是直接取平均sigmoid(CM)|
|人类风险认证上界|需要固定policy后独立的新目标真人标签及高置信程序；本次没有获得|

新算法还使用ONS的**标签前预测**设计查询，不能将其与固定CM的`f`或已经校准的人类概率混同。经过LURE/control-variate校正的训练成本可为负或超过1；它是估计量，不应再用sigmoid或裁剪成概率。
