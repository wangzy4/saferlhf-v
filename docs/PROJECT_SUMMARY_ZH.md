# SafeRLHF-V 复现总结：目标、方法主线与当前进展

> 最新状态：2026-10-10。旧四策略Luna PK完成384项计划（379有效/5失败），两个Qwen任务已按用户要求停止。新算法N32/b8/T4完成四轮真实RL、严格重载与全轮回放，新增32条AI-proxy标签、0真人，仍NOT_CERTIFIED。
>
> 详见 [Luna最终报告](LUNA_AUTHOR_PK64_20261010_ZH.md)、[N32工程报告](ACTIVE_SAFETY_V2_N32_ZH.md)、[RM/CM sigmoid解释](ACTIVE_SAFETY_METRICS_ZH.md) 与 [阶段汇报](PROGRESS_REPORT_ZH.md)。第4节是旧复现的32次更新设置，第5节保留历史评测经过；不与新算法线性dual或当前状态混同。

## 1. 我们要回答什么问题？

复现 [SafeRLHF-V](https://github.com/saferlhf-v/saferlhf-v)（[论文](https://arxiv.org/abs/2503.17682)），不只追求“脚本能跑”，而是检查：

1. 作者公开的安全策略，相对原始视觉语言模型究竟改善了什么？
2. 根据公开方法自行训练的帮助性评分模型 RM 和安全成本模型 CM，能否学到有泛化能力的信号？
3. 使用这些评分器做带成本约束的 RL，能否提高生成安全性，同时保留帮助性？
4. 若小规模实验有效，再考虑扩大训练，检查能否接近论文结果。

当前聚焦 **LLaVA-1.5-7B**。尚未找到作者最终使用的 RM/CM 的公开下载来源，因此使用我们自行训练的评分器；**它们不是作者原始 checkpoint**。

## 2. 方法主线：先把测量做可信，再推进策略训练

```text
固定模型、数据与评测协议
        ↓
复核原始基座 / 作者公开策略的推理
        ↓
训练 RM / CM，并检查排序、成本符号与独立泛化
        ↓
真实六模型 RL + PTX 小预检，验证更新、保存和恢复
        ↓
两种初始化分别做固定预算的短程 RL
        ↓
在冻结的同一批题上比较训练前后生成，外部逐题评判
        ↓
根据策略质量而不是“训练成功”决定是否扩大规模
```

这条路线刻意区分三件事：**工程可执行、评分模型有效、最终策略有效**。前两者是后者的必要条件，但不能代替后者。

## 3. 已经完成了哪些有意义的实验？

### 3.1 作者公开策略与基座：590 题有效推理比较

对 BeaverTails-V 官方 evaluation 的 **590 题、20 类**，使用一致的生成与评分设置比较原始基座和作者公开策略。

| 对数据已有回答的偏好代理 | 原始基座 | 作者公开策略 |
| --- | ---: | ---: |
| 帮助性偏好一致率 | 58.31% | 66.78% |
| 安全性偏好一致率 | 39.15% | 42.54% |

作者策略在这个帮助性代理上改善更明显，安全性代理改善较小；其生成通常更长、重复较少，但风险抽查仍发现不安全配合。

**这些是对已有回答的概率倾向，不是新生成回答的安全率，也不是论文的 GPT 成对胜率。** 结果支持继续研究，不支持可靠安全部署的结论。详见 [推理结果](RESULTS_LLAVA_ZH.md) 与 [指标定义](METRICS_ZH.md)。

### 3.2 RM / CM：从小试验推进到 1K 全参数评分训练

先做 LoRA 和较小的全参数试训，发现“模型能保存”并不意味着 CM 能正确识别风险：一些早期 CM 把验证回答全部判为安全。这些失败保留为历史记录，**没有接入 RL**。

目前用于 RL 的评分器来自新的一轮 **20 类、1,024 条训练＋256 对冻结内部验证**，从基座重新训练，固定完成 **3 epochs**：语言骨干、图像投影层和评分头全量训练，冻结视觉编码器。

- RM 学习更有帮助的回答得分更高。
- CM 学习更危险的回答成本更高，并用安全标签约束成本符号；`cost > 0` 对应有害。
- 训练与内部验证来自源 train split，排除历史样本和官方 evaluation 的精确 RGB 图像重复。
- 按预定最终 epoch 报告，不用验证结果挑中间最好的 checkpoint。

| 最新全参数 1K 评分器指标 | 最终结果 |
| --- | ---: |
| RM 验证排序准确率 | **75.78%（194/256）** |
| CM 验证排序准确率 | **80.08%（205/256）** |
| CM 安全标签准确率，阈值 0 | **85.94%（440/512）** |
| CM 平衡安全标签准确率 | **85.87%** |
| CM AUC | **0.932** |

另冻结 **80 对未用于我们评分器训练的新内部验证样本**，得到：

- RM 排序：**75%（60/80）**。
- CM 排序：**80%（64/80）**。
- CM 安全标签：**86.25%（138/160）**。

独立检查仍有正面信号，因此值得尝试小规模 RL。但训练集排序约 98%–99%，明显高于验证；CM 仍有漏检和误报，不能当作完美安全判断器。全部 256 对保存重载分数一致，最新 RM/CM 的 HF 私有归档及远端哈希核验已完成。详见 [评分器训练结果](RESULTS_RM_CM_ZH.md)。

**不能把这些内部指标直接与论文 Table 4 相减，或据此宣称接近论文策略效果：训练量、数据划分和验证协议不同。**

## 4. RL 现在怎么做，进展到了哪里？

### 4.1 固定评分器，比较两种策略初始化

分别从以下两个初始化训练，保持方法、评分器和预算一致：

1. **原始 LLaVA-1.5-7B**：观察我们的小规模训练是否能引入安全约束。
2. **作者公开 SafeRLHF-V policy**：观察在已有安全策略上继续训练的收益或退化。

每个实验有六个独立模型角色：可训练 actor、冻结 reference、冻结 RM、冻结 CM，以及各自独立可训练的 reward critic 和 cost critic。两个 critic 从对应的 1K 评分器初始化，**不能拿共享的只读模型冒充 critic 训练**。

保留仓库原生的 **PPO、逐 token KL、GAE、成本约束与 PTX**：既优化帮助性，又惩罚安全成本，并用额外的指令学习维持模型能力。保留仓库的 log-space 成本乘子更新；它与论文公式存在实现差异，不把两者说成逐项完全一致。

当前使用实验 runner 调用原生训练方法，而不是声称已完整认证作者原始入口及所有续训情形。

### 4.2 真实训练预检已通过

已完成 **16 个训练 prompt、六个独立模型、4 卡**的小预检：实际执行 **2 次 RL＋PTX 联合 actor 更新**，两个 critic 各更新 2 次，真实参数梯度检查通过。模型保存、独立重载和有限范围的 actor 恢复检查均通过；额外完成 **1 次恢复后真实联合更新**，不写回预定最终策略。

预检强制了不同 EOS 长度，**只用于覆盖变长生成，不用于评价策略质量**。恢复检查包括优化器状态抽样，不是三个训练角色、RNG 和数据游标的完整续训认证。聚合验收见 [真实 RL 预检记录](results/rl-native-six-model-tiny-v3.json)。

### 4.3 正式小规模 RL：两组训练与最终策略验收完成

预检通过后执行 **base → 作者安全策略** 的串行流程。2026-10-09 17:33 核查时，两组均已完成 **32/32 次联合更新**、两个 critic 各 32 次更新、最终策略保存和独立重载验收。基座组训练阶段约 42.3 分钟，作者策略组约 57.2 分钟。任一阶段失败即停止，不自动覆盖失败产物或跳过验收。

| 固定配置 | 本轮安排 |
| --- | --- |
| RL 数据 | **64 个训练 prompt**，覆盖 20 类 |
| 内部验证 | 另固定 **64 条**，不用于选择 epoch |
| PTX | 论文使用的 Align-Anything TI2T Instruction-100K 来源，固定 **128 条**子集 |
| 训练预算 | **2 epochs / 每个初始化 32 次联合 actor 更新** |
| Critic | reward / cost critic 各 **32 次更新** |
| 全局 RL prompt batch | **4** |
| Actor / critic 学习率 | **5e-7** |
| 生成 | sampled，最多 **512 个新 token**；正式训练不强制 EOS、不静默截断 |
| 模型选择 | 固定最终 epoch，不根据验证或外部评判选择 checkpoint |

这是参考作者公开方法后缩小的探索实验，**不是完整训练量复现，也不预设 32 次更新足以达到论文效果**。PTX 仅是固定首 shard 的 128 条子集，不是完整 100K 数据。

## 5. 如何判断“训练真的有用”？

### 评测集与训练集严格分开

- **内部 64 条验证**来自 train-source，不能称为作者策略未见过的测试集。
- 另从官方 **590 题 evaluation** 按固定种子、20 类轮转冻结 **64 题、64 个不同图像**，不按模型分数或答案选样。
- 官方 evaluation 不参与我们的训练、调参或 checkpoint 选择。
- 外部 64 题此前参与过全量推理诊断，**不是全新盲测**。
- 训练前后的评测生成固定为 **greedy、最多 512 个新 token**，使用匹配的 processor 和提示模板；本轮重新生成全部四套各 64 条回答，冻结题目 ID 与图像哈希核验通过。

### 外部评判与费用：历史经过

当前最终状态为Luna379有效/5失败、Qwen停止，见顶部报告。以下保留旧协议与早期断点，不是尚待启动的任务。

对每个训练后策略，分别与**自身初始化**比较帮助性和安全性。最初的外部改编协议计划是：

**64 题 × 2 个初始化 × 2 个评判维度 = 256 次主评判请求**，不是 64 次。

历史外部路线曾采用用户确认的 **prism `gpt-5.6-terra`**：文本测试成功，但首题图文pilot被接口拒绝，返回“不支持多模态／文件附件”，没有有效样本判分。当前可用路线为下面核验的 **iiot Luna**，使用作者联合两维度原prompt，而非继续旧拆维度256请求协议。逐请求记录原文、usage和失败；没有可信价格／billing时只报token，不估算金额。

用户仅授权这份冻结外部 64 题的数据用于外部评判；**训练集、内部验证和其余 evaluation 题不外传**。已提交冻结首题的图文 pilot 请求，但被接口拒绝，未取得成功 completion 或 usage。

**2026-10-09 22:45 再查 prism 的 Luna：**按用户要求，对 prism 通道的 `gpt-5.6-luna` 各发送一次纯文本可用性请求和合成图片请求，两次均返回 **HTTP 503／`model_not_found`**，该通道无可用模型路由。没有发送正式样本，未做自动重试或纯文本标注降级。不能把这个结果推广到其它服务通道。

**iiot Luna历史断点（2026-10-09）：**23:01标准OpenAI SDK（自动重试关闭）通过文本、两张换色图和作者完整Appendix C首条试标，首条2,918输入／674输出tokens，约8.9秒。用户授权继续后，前5题六组全配对共30条已全部遍历，**29有效／1拒收**，包含明确复用首条，实际新增29次请求。拒收输出状态completed、含完整12标签，但额外追加两个排序标签，违反当前本地严格解析约定；不是路由故障或截断。试标门禁未通过，**进程已停止，完整384次榜尚未启动**，剩余354次未发送；原失败未修补、未重试。新增请求用量112,576输入／21,470输出tokens（含拒收请求），没有可信金额。后续先审查原文和解析约定，再显式接续，不能根据有利分数挑结果。

按用户要求，另选 **Qwen3.5-27B**（2026 年 2 月发布、原生视觉语言模型）开展独立本地试验，已完成部署、两张合成图的看图验收及前 5 题共 20 次试评，随后获用户授权运行完整冻结 64 题 PK（256 次判分）。截至 2026-10-09 20:57，共取得 **114/256 次格式有效判分**：基座组前 57 题的两维度已完成；第 58 题帮助性输出达到 1,200 token 上限并截断，程序停止，作者策略组尚未开始。失败记录保留，不自动重试；失败解释出现帮助性／安全性标准混淆，已文本审阅全部 57 条帮助性理由，至少 14 条违背维度分离要求。历史基座组帮助性／安全性强制胜率为 47.4%／56.1%，平均分变化为 −0.018／−0.088，不作为可靠改善证据。

按用户进一步要求，复现主线改为从论文 LaTeX 源码直接提取的 **Appendix C 完整原 prompt**，一次请求联合评两维度，保留 12 个原标签，不再用短 JSON 改编协议。四套生成回答对全部六组配对，每组 64 题，共 **384 次请求／768 个维度偏好**，分别出帮助性和安全性榜并单列训练前后对比。**2026-10-09 23:25** 已完成 **53/384次有效请求、1次拒收**，后台进程存活；拒收原因是标签前额外文字，输出未截断。此前拆维度 prompt 的运行仅留作独立诊断，不混入主榜。Qwen 权重、全部既有解码设置（含 1,200 token 上限）不变；每题一次尝试，失败单独记账。论文裁判为 GPT-4o，原 API 解码及超长恢复实现未公开，因此不将本地替代裁判结果说成论文等价结果；详见 [PK 实现核查与部分结果](PK_EVALUATION_ZH.md)。Qwen为本地评测，不上传样本；Luna仅外传已授权冻结数据。完整榜未完成前不下策略质量结论。

论文原评判器为 GPT-4o；后续采用指定替代评判器时会明确注明协议差异，不冒称完全复现原论文胜率。

## 6. 环境与资源，简述

主要使用 **4 × NVIDIA H20（每卡约 96GB 显存）**，两个初始化串行运行。Python 3.11、PyTorch 2.5.1 / CUDA 12.4、Transformers 4.48.3、DeepSpeed 0.16.2。

评分器训练使用全参数语言骨干方案；RL 使用 BF16、ZeRO-3 和 CPU 优化器卸载。CPUAdam 是适配本次资源的工程选择，与作者 FusedAdam 环境不同。最新 1K 评分器每个模型纯训练约 **20 分钟**；本轮正式 RL 训练阶段基座组约 **42.3 分钟**、作者策略组约 **57.2 分钟**。Qwen 试评使用独立环境，不改变上述训练环境。

## 7. 当前结论与下一步

**当前能够确认：**旧两种初始化训练与四套回答已交付，Luna384个计划项已完成；新算法四轮工程验收通过、128候选/32新代理标签，最终policy官方64题有50条文本变化。

**当前不能确认：**新算法的预算匹配性能优势、人类风险改善、断点续训或可靠部署。新policy固定自训RM均值上升而CM也上升，不能称安全改善；尚未做新policy Luna PK。精确图像排重不等于语义/近重复去重。

下一步按顺序：

1. 验收新算法完整resume；不重复旧384项或恢复停止的Qwen任务。
2. 开展预算匹配、多种子uniform/no-CV、uniform/CV、fixed-beta、joint对照，另行核算资源。
3. 若开展新policy外部PK，独立编排、确认授权，不混旧策略榜。
4. 固定候选后做直接图像真人candidate/reference认证；当前train标签为AI proxy，cert/ref尚为0。

继续工作的原则是：**不把评分准确率当成策略胜率，不把工程成功当成安全成功，不根据官方 evaluation 调参，不为得到漂亮结果挑 epoch。**

更多历史结果见 [复现进展](REPRODUCTION_ZH.md)、[RM/CM 结果](RESULTS_RM_CM_ZH.md)；实现和排错细节另见 [开发记录](development/README.md)，不在本文展开。
